# Dependency adoption

## Release adoption — 2026-10-01

SLC adopts Playbook 17.3.0 and Cligent 0.30.0. Playbook 17.3 changes no vendored definition and no published sidecar — it adds the host-level subagent effort, resolves an unset Claude subagent model to the agent's own in its launcher's configuration, and requires Cligent 0.30 — so the engine contract (`RUNTIME_ABI` `1`, a frozen `SUPPORTED_ARTIFACT_SCHEMAS` of `[3]`), the compiled-execution sections, and the vendored set are those of 17.2.0, every bundle and both demo references are retained, and the regenerated pins change only the lockfile identity, the link-target identities, and their provenance. Cligent 0.30 adds `subagentEffort` and the subagent definitions its Claude adapter registers for it, which the compiler's own agent does not set, and SLC reads its own configuration rather than Playbook's launcher blocks, so a compile's queries are unchanged. Cligent 0.30 adds the subagent effort as a fourth `AgentAdapter` type parameter whose default keeps SLC's adapter factory annotation, `AgentAdapter<string, boolean, string>`, assignable, so the build needs no source change. SLC's direct Cligent dependency moves to `^0.30.0` with Playbook's, so the lock resolves one Cligent and one engine. Cligent 0.30 tests the same agent SDKs as 0.29, so the locked development SDKs stay at Claude Agent SDK 0.3.284 and Codex SDK 0.159.0. The validation passes 1,535 tests with two skips, immutable definitions, both demos, artifact reviews, and reproducible pins.

## Release adoption — 2026-09-28

SLC adopts the published Playbook 17.0.0 package ahead of the final Playbook 17.1.0 and Cligent 0.28.0 set, which is not yet published. Its engine still declares ABI 1 and artifact schema 3 — `RUNTIME_ABI` `1` and a frozen `SUPPORTED_ARTIFACT_SCHEMAS` of `[3]`, read from both installed engines — and the three compiled-execution sections are byte-identical to 16.0.0's. Of the eight vendored files only two change. `gears2fsm.md` admits the Captain's payload-free `recover` action in the controller contract where a Source declares recovery preparation, which SLC's controller discriminator already accepts ([DR-053](../specs/decisions/053-recovery-controller-discrimination.md)). `link.md` specifies that a failed step retries only from its saved invocation checkpoint instead of an `entryEvent.contextField` replay, describes step records and recovery offers, and has shared and bespoke judge prompts state the `{ blocked: … }` answer when no declared outcome matches. The published sidecar is unchanged, so the SLC-owned sidecar needs no edit. No new runtime profile or agent rebuild is required under [DR-028](../specs/decisions/028-contract-based-adoption-without-recompilation.md): the pin generator's compiled-execution gate, the three independent artifact reviews, the generated bundle suites, and both demo references pass against the installed engine, and regenerated pins record the published dependency and lockfile.

Playbook 17 requires Cligent `^0.27.0`, the release SLC already depends on, so the lock resolves one Cligent 0.27.0 where Playbook 16's `^0.26.0` requirement had kept a nested second copy. The retained text2gears and gears2fsm bundles still declare the deprecated `entryEvent.contextField`, which the 17 engine's types accept and its runtime ignores; the compiled executor never retries through the control surface, so nothing SLC runs depends on it. The locked development SDKs are Claude Agent SDK 0.3.283 and Codex SDK 0.158.0. The validation passes 1,535 tests with two skips, immutable definitions, both demos, artifact reviews, and reproducible pins.

## Release adoption — 2026-09-26

SLC 0.11.0 adopts the published Playbook 16.0.0 package. Its engine still declares ABI 1 and artifact schema 3, and all three compiled-execution sections are unchanged from the retained bundles. The five vendored definitions and every published local input are synchronized byte-identically, including the workflow catalog, link materializer, and prefix tool. The definitions bind shared calls to the catalog, identify accepted outcomes at their next public snapshot (including parallel joins), and link supported parallel groups through the shared engine. The SLC-owned sidecar includes the catalog in the text2gears closure, and regenerated pins record the published dependency and lockfile. No new runtime profile or agent rebuild is required under [DR-028](../specs/decisions/028-contract-based-adoption-without-recompilation.md); all three retained meta-phase bundles and both demo references pass their generated and independent checks against the installed engine.

SLC retains direct Cligent 0.27.0 and Spex 3.0.0 dependencies. The locked Claude Agent SDK is 0.3.282. The default pipeline applies `optimize` and `prefix` before `gears2fsm`; `--no-optimize` skips both passes. The Source-fidelity check accepts each prompt's Source-order or prefix-first layout without depending on a separate prefixed-prompt section ([DR-052](../specs/decisions/052-prefixed-prompt-acceptance.md)).

The release validation passes 1,517 tests with two skips, immutable definitions, release metadata, reproducible pins, both demos, and the 181-file installed-package smoke. The installed candidate also passes cold compilation, exact unchanged reuse, incremental Update/Reuse, and a real-agent run with a successful durable terminal and a verified committed repair on Opus 5.5. Scratch-only signing overrides accommodate the local global signing setting; registry and model interruptions were resumed without repeating completed gates or rebuilding the unchanged candidate.

## Dependency adoption checkpoint — 2026-09-12

The working repository selects current published dependencies for the next experiments. **The dependency adoption passes release validation.** The isolated experiment cohort is frozen separately before provider measurements. The [version record](performance/dependency-baseline-2026-09-12.json) captures every top-level manifest range, locked and installed version, manifest/lock hashes, and private audit identities. This is a dependency checkpoint, not a new compilation-speed result ([IR-040](../specs/intents/040-current-dependency-baseline.md)).

Runtime selections are Cligent 0.27.0, Playbook 13.2.0, Spex 3.0.0, XState 5.33.0, YAML 2.9.1, TypeScript 6.0.3 and Node declarations 25.9.6. The registry's `npm outdated` audit reports only the intentional TypeScript and Node-declaration exceptions. `@types/node` stays at `^25.9.6` for the current Node 25 environment: `latest` points to the older 22.20.2 line, while `ts6.0` points to 26.5.1. A dist-tag alone does not establish the appropriate runtime declaration version.

TypeScript 7.0.2 supplies the native development build through `@typescript/native: npm:typescript@^7.0.2`. SLC retains direct `typescript: ^6.0.3` for its stable compiler APIs; native 7 does not provide compatible `createProgram`/`createSourceFile` exports. The build explicitly invokes `node node_modules/@typescript/native/bin/tsc --project tsconfig.json`, avoiding competing `tsc` executable names. Native platform optional dependencies must remain installed. The private audit proved that the official compatibility wrapper 6.0.2 forwards compiler 6.0.3, but the selected manifest does **not** adopt that wrapper. Native emission and execution of a synthetic TypeScript-API consumer and the repository build passed. Microsoft documents the [TypeScript 7 API compatibility boundary](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

Spex 3 changes both published grammar files; they are not byte-equivalent to 0.3. The reviewed English pattern removes the leading `The` and permits related behaviors; the Chinese wording also changes. Existing package locators remain valid. Playbook still owns fixed-English actor, result and placeholder syntax. The repository's own `specs/meta.md` was not migrated ([DR-016](../specs/decisions/016-gears-grammar-provenance.md)).

Installed Playbook 13.2 declares ABI 1 and schema 3. Its three Compiled execution sections remain identical to the reviewed prior definitions; its link definition changes continuation composition. Bundle retention requires regenerated identities, generated suites and independent installed-engine checks under [DR-028](../specs/decisions/028-contract-based-adoption-without-recompilation.md). Compatibility corrections cover current fresh/resumed continuation formats without relaxing exact Q&A checks, and complete Source-fragment attribution without mistaking contained relay text for a reorder. All three meta bundles and both demos pass independent retention review: 56 of 74 recorded files are byte-identical, three FSM changes exactly match formatting with unchanged ASTs, and fifteen checker-support files match the current compiled and formatted verifier. No model rebuild was needed.

Claude SDK 0.3.270 and Codex SDK 0.154.0 are development dependencies, but real compiler adapters import those installed SDKs. Their placement does not make them irrelevant to provider measurements or install them automatically for production consumers.

Private audits are retained under `/private/tmp/slc-spex-adoption-audit` and `/private/tmp/slc-typescript-7-audit`; the JSON also hashes the registry snapshots. The [historical reproduction](compilation-reproduction.md) privately installs commit `6ba16d0`'s old lock for Claude. Its unused Codex SDK is 0.146.1 versus the measured graph's 0.153.4. The accepted 196.601-second minimal result used Playbook 12.3 and the earlier dependency graph; it is not evidence for this new graph.

The full working-tree suite passed 1,326 tests with two skips, including the separately prepared phase recorder. Formatting, ESLint, native build, definitions, release-workflow audit, current pins, and the 177-file package smoke passed. Both demo runtime smokes passed with signing disabled only for their disposable synthetic commits. Independent retention evidence is `/private/tmp/slc-current-retention-review/evidence.json`.

Published DEV exposes a private two-argument helper through its verification export while its runtime uses the correct three-argument composer. SLC records that raw finding and verifies the actual runtime composer through an isolated copy. The upstream export correction stays on the authorized Playbook branch until published; the registry dependency remains untouched.
