# Dependency adoption

## Release adoption — 2026-09-24

SLC adopts the published Playbook 15.1.0 package. Its engine still declares ABI 1 and artifact schema 3, and all three compiled-execution sections are unchanged from the retained bundles; `link.md` changes only the TypeScript interface excerpts that describe the failure-cause and control-standing contract Playbook 14.1 added. The vendored set gains the `prefix` pass definition and its `prefix-prompts.mjs` tool, which the published sidecar declares as the pass's local input; the SLC-owned sidecar declares the pass's flattened closure the way it declares `optimize`'s, the definition gate verifies all five definitions and every published closure member, and regenerated pins record the new exact dependency set. No new runtime profile or agent rebuild is required under [DR-028](../specs/decisions/028-contract-based-adoption-without-recompilation.md).

SLC keeps its direct Cligent 0.27.0 dependency; Playbook's declared `^0.26.0` requirement resolves separately in the lock. Playbook 15.0 names its shared configuration directory `config/`, so the demo checker seeds its scratch host configuration there rather than at the former location the host would relocate. The maintained reference bundles Playbook ships are unchanged until their next recompile, so the installed workflows carry no prefixed prompt yet, and the Source-fidelity check over them exercises no `## Prefixed prompts` section.

## Dependency adoption checkpoint — 2026-09-12

The working repository selects current published dependencies for the next experiments. **The dependency adoption passes release validation.** The isolated experiment cohort is frozen separately before provider measurements. The [version record](performance/dependency-baseline-2026-09-12.json) captures every top-level manifest range, locked and installed version, manifest/lock hashes, and private audit identities. This is a dependency checkpoint, not a new compilation-speed result ([IR-040](../specs/intents/040-current-dependency-baseline.md)).

Runtime selections are Cligent 0.27.0, Playbook 13.2.0, Spex 3.0.0, XState 5.33.0, YAML 2.9.1, TypeScript 6.0.3 and Node declarations 25.9.6. The registry's `npm outdated` audit reports only the intentional TypeScript and Node-declaration exceptions. `@types/node` stays at `^25.9.6` for the current Node 25 environment: `latest` points to the older 22.20.2 line, while `ts6.0` points to 26.5.1. A dist-tag alone does not establish the appropriate runtime declaration version.

TypeScript 7.0.2 supplies the native development build through `@typescript/native: npm:typescript@^7.0.2`. SLC retains direct `typescript: ^6.0.3` for its stable compiler APIs; native 7 does not provide compatible `createProgram`/`createSourceFile` exports. The build explicitly invokes `node node_modules/@typescript/native/bin/tsc --project tsconfig.json`, avoiding competing `tsc` executable names. Native platform optional dependencies must remain installed. The private audit proved that the official compatibility wrapper 6.0.2 forwards compiler 6.0.3, but the selected manifest does **not** adopt that wrapper. Native emission and execution of a synthetic TypeScript-API consumer and the repository build passed. Microsoft documents the [TypeScript 7 API compatibility boundary](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

Spex 3 changes both published grammar files; they are not byte-equivalent to 0.3. The reviewed English pattern removes the leading `The` and permits related behaviors; the Chinese wording also changes. Existing package locators remain valid. Playbook still owns fixed-English actor, result and placeholder syntax. The repository's own `specs/meta.md` was not migrated ([DR-016](../specs/decisions/016-gears-grammar-provenance.md)).

Installed Playbook 13.2 declares ABI 1 and schema 3. Its three Compiled execution sections remain identical to the reviewed prior definitions; its link definition changes continuation composition. Bundle retention requires regenerated identities, generated suites and independent installed-engine checks under [DR-028](../specs/decisions/028-contract-based-adoption-without-recompilation.md). Compatibility corrections cover current fresh/resumed continuation formats without relaxing exact Q&A checks, and complete Source-fragment attribution without mistaking contained relay text for a reorder. All three meta bundles and both demos pass independent retention review: 56 of 74 recorded files are byte-identical, three FSM changes exactly match formatting with unchanged ASTs, and fifteen checker-support files match the current compiled and formatted verifier. No model rebuild was needed.

Claude SDK 0.3.270 and Codex SDK 0.154.0 are development dependencies, but real compiler adapters import those installed SDKs. Their placement does not make them irrelevant to provider measurements or install them automatically for production consumers.

Private audits are retained under `/private/tmp/slc-spex-adoption-audit` and `/private/tmp/slc-typescript-7-audit`; the JSON also hashes the registry snapshots. The [historical reproduction](compilation-reproduction.md) privately installs commit `6ba16d0`'s old lock for Claude. Its unused Codex SDK is 0.146.1 versus the measured graph's 0.153.4. The accepted 196.601-second minimal result used Playbook 12.3 and the earlier dependency graph; it is not evidence for this new graph.

The full working-tree suite passed 1,326 tests with two skips, including the separately prepared phase recorder. Formatting, ESLint, native build, definitions, release-workflow audit, current pins, and the 177-file package smoke passed. Both demo runtime smokes passed with signing disabled only for their disposable synthetic commits. Independent retention evidence is `/private/tmp/slc-current-retention-review/evidence.json`.

Published DEV exposes a private two-argument helper through its verification export while its runtime uses the correct three-argument composer. SLC records that raw finding and verifies the actual runtime composer through an isolated copy. The upstream export correction stays on the authorized Playbook branch until published; the registry dependency remains untouched.
